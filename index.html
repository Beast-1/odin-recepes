About

The part after the demo is the part I actually like.

Plenty of AI/ML work stops once something runs in a notebook. I'm more interested in what happens after that: turning it into software that holds up when other people depend on it. That's been the throughline behind an autonomous 3D-content pipeline I call ARGUS, a handful of LLM agents built for specific jobs rather than general chat, and the web apps that make any of it usable.

Most days that's Python for the ML and backend work, React on the frontend, Supabase handling the infrastructure I'd rather not build myself, and Flutter when something needs to run on a phone.

Process

How this usually goes

Roughly the same four stages every time, in whatever order the project actually needs them.

  1. 01

    Explore

    Figure out what the problem actually is before opening an API reference.

  2. 02

    Build

    Get something working in front of real data quickly, even if it's rough.

  3. 03

    Refine

    Cut the parts that don't earn their place, fix what breaks under real use.

  4. 04

    Ship

    Out of my hands and into someone else's, not sitting in a demo folder.
